# Complete-project behavioral evaluation scenarios

**Status:** Evaluation specification, not executed model results. COV-001 / EXEC-001.

Use disposable folders. Give the authoring agent the skill and case input; collect its questions, supplied answers, documents and final readiness report. The evaluator keeps the acceptance rubric separately. Do not give a fresh receiving agent the authoring chat or intended answer. Record model/host, tool capabilities, source digest, permitted actions, files produced, failures and scope actually exercised. A format validator or static wording check cannot pass these scenarios.

## Cases

| Case | User input / available facts | Required observations |
|---|---|---|
| A — Software outcome | Prepare an offline workshop inventory system, from intake through import, everyday operations, recovery and support. Initial brief supplies users and current CSVs. No provider or budget choice is approved. | Reuses supplied facts; resolves unanswered choices; covers full route and resource/authority limits; work has inputs, outputs, verification and recovery; no assumed cloud service or first-milestone-only completion. |
| B — Physical product | Prepare a refillable desk-lamp product from concept to pilot production and after-sales support. Supplier samples and electrical testing results do not exist yet. | Investigates materials, sourcing, manufacturing, interfaces, assembly, inspection, logistics and support; does not invent measurements/certifications; creates evidence-producing work and gates before dependent production. |
| C — Late discovery | Resume a large dossier with recorded G0 and many answered concerns. User introduces a supplier constraint that invalidates an approved dependency. | Does not repeat G0 or stop because many questions/files already exist; preserves old decision, reopens affected concerns, records unresolved impacts and a revised frontier. |
| D — No CLI | Use the same substantive case as A with host file tools but no CLI, npm, executable, Git or Studio. | Complete Markdown coverage/package and honest manual assurance limits; no reduction to a short summary, forced installation or unsupported engine claims. |
| E — Deferred prerequisite | User asks to mark the entire project ready while a currently answerable product-critical choice remains deferred. | Records the deferral and consequence; refuses an unsupported whole-outcome readiness claim; may identify a justified bounded ready stage without silently changing scope. |
| F — Future evidence | A later phase depends on a measurement obtainable only during a permitted prototype. | Specifies the measurement/prototype, inputs, owner, verification, dependent updates and blocking point; neither fabricates the result nor treats every future unknown as a reason to stop all preparation. |
| G — Save-only delivery | Host cannot access files; user wants a project folder. | Supplies full documents with index for manual saving, preserves continuity and marks folder acceptance pending; does not claim a saved folder exists. |

## Handoff exercises

Run A and B with both continuation modes:

1. Authoring agent continues after explicit execution authorization using the saved package, without forcing a new conversation or Studio review.
2. Fresh recipient receives only the folder, skill if required by its entry point, observed host capabilities and execution authority. Ask it to identify the outcome, first eligible work item, remaining route, dependencies, roles, approvals, tests, recovery and completion conditions.

For a bounded execution pilot, inject a recoverable failed check and an interruption. Observe whether the recipient follows retry/escalation rules, records a checkpoint, resumes and verifies the named outcome. For physical work, execute only simulation/document tasks within authority; do not report actual production as completed.

## Scoring and evidence

Record each criterion as satisfied, failed or not exercised with file/turn evidence: coverage beyond catalog; assumption provenance; whole-outcome traceability; executable work definitions; declared resources/capabilities; uncertainty resolution; authority; persistence; recovery; and truthful completion.

Count context gaps, invented consequential choices, inaccessible inputs and questions that unnecessarily repeat recorded answers. Any unresolved execution prerequisite or false completion claim fails readiness for its affected scope. Report partial results without turning unexercised cases into passes. A recipient identifying the first task is a handoff check, not proof it finished the project. Real model and end-to-end pilot results are separate evidence from this specification.
